# Exception Handling & Recovery Playbook

Autonomous subagents fail in predictable ways. Classify the failure before reacting—never blindly retry the exact same command in a loop, and never give up prematurely on recoverable issues.

| Exception Class | Detection Signal | Recovery Strategy |
|---|---|---|
| **1. First-run unconfigured (`SETUP_REQUIRED`)** | Exit code `2` or `claude-subagent doctor` shows `configured: false` | Run `claude-subagent setup --discover`, ask the user to confirm default model + delegation/usage policy, persist via `claude-subagent setup ...`, then proceed. Never silently guess a model. |
| **2. Review findings / failing tests** | Reviewer flags concrete defects or verification tests fail | Resume the owning implementer (`claude-subagent send <id> -C <repo> "..."`) with exact `file:line` findings and failing output; re-verify and repeat until checks genuinely pass. Break out only on external blockers, ambiguous product requirements, or 2+ identical failures. |
| **3. User / host contention (GUI, desktop, shared editor)** | User is actively moving mouse/typing, window focus shifts unexpectedly, or app lock is held by user | **Yield immediately.** Pause automated GUI/host actions (or run `claude-subagent stop <id>` if needed) and wait or inform the user cleanly rather than fighting for focus. |
| **4. Usage policy / scope reminder triggered** | Task hits a boundary noted in `policies.usagePolicy` (e.g., user asked to be reminded in certain situations) | Pause briefly to remind the user before dispatching, and proceed or adjust according to their reply. |
| **5. Timeout, interruption, or stale PID** | Exit code `1` with `Timed out`, mid-run crash, or `claude-subagent ps` shows `interrupted (stale pid)` | Run `claude-subagent show <id> -C <repo>` and `git status --short` first—partial work is often already on disk—then continue with `claude-subagent send <id> -C <repo> "Continue from where you stopped."` instead of restarting from scratch. |
| **6. Write ownership or merge conflict** | Two workers touched overlapping code or shared-cwd git deltas blur ownership | Isolate concurrent writers in separate `-w <name>` worktrees; halt colliding writers (`claude-subagent stop <id>`), resolve integration at the coordinator level, and never silently overwrite another worker's or the user's uncommitted edits. |
| **7. Provider outage / 429 rate limit / auth error** | HTTP 429/5xx, network timeout, or expired credentials | On transient network/429 errors, retry with bounded backoff or pass `--fallback-model`. On auth/quota exhaustion, **never** silently switch to an unauthorized paid route—report the exact provider error and let the user choose (or confirm a `-m` / `--provider` override). |
| **8. Stale or wrong session context** | Resumed session goes off-track or carries conflicting prior assumptions | Start a fresh session—or branch from an earlier clean state with `claude-subagent fork <id> -C <repo> "..."`—and optionally clean up stale entries with `claude-subagent rm <id>`. |
